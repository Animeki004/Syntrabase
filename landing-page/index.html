Getting Started • Architecture

Overview & Architecture

Syntrabase is an open-source, multi-tenant developer platform engineered as a high-performance, drop-in replacement for Google Firebase. While Firebase relies on closed Google Cloud primitives with unpredictable pay-per-read billing models, Syntrabase runs natively on PostgreSQL 16 JSONB.

Predictable $5/Month Fixed Infrastructure: Run your entire SaaS (Auth, Firestore, Storage, Realtime) on a single $5/mo VPS with 10M+ operations instead of risking unbounded $10,000+ cloud bills.

The Syntrabase ecosystem consists of two first-class SDK packages:

  • @syntrabase/client-sdk@^1.2.0: Tree-shakeable, modular client library for browsers and mobile applications matching Firebase v9/v10 functional syntax.
  • @syntrabase/admin-sdk@^1.2.0: Privileged Node.js server library using master sk_live_... keys for backend microservices, Next.js server actions, and background workers.
Installation • Packages

Installation & Package Ecosystem

Install the modular client SDK in your web application (Next.js, Vite, React, Vue, Svelte, or Vanilla JS):

npm install @syntrabase/client-sdk@^1.2.0

For Node.js backend servers, server actions, or administrative microservices, install the admin SDK:

npm install @syntrabase/admin-sdk@^1.2.0
Configuration • Security

Configuration, Keys & Environments

Syntrabase enforces strict separation between public client credentials and privileged master secrets. Never leak master secrets into frontend client bundles:

Security Protocol: Publishable keys (pk_live_...) are safe for browser code and obey Security Rules. Master secret keys (sk_live_...) are restricted to backend servers and bypass all client security rules. 
# Frontend Application Environment (.env.production)
NEXT_PUBLIC_SYNTRABASE_URL=https://api.yourdomain.com
NEXT_PUBLIC_SYNTRABASE_PROJECT_ID=saas-production-app
NEXT_PUBLIC_SYNTRABASE_API_KEY=pk_live_839a7b1c4e6f9d2a015b7e8c3f

# Server-Side Only Backend Environment (Never bundle in client)
SYNTRABASE_SECRET_KEY=sk_live_your_admin_secret_key_sample
SYNTRABASE_ENVIRONMENT=production # 'production' | 'staging' | 'development'

Client SDK • ACID Transactions

Batch Writes & Transactions

Syntrabase brings true PostgreSQL ACID transactional integrity to modular Firestore code. Read-modify-write transactions auto-retry on conflict and roll back cleanly on errors: 

import { 
  getFirestore, 
  doc, 
  runTransaction, 
  writeBatch, 
  increment 
} from '@syntrabase/client-sdk';

const db = getFirestore(app);

// 1. ACID Transaction (E-Commerce Stock Purchase)
await runTransaction(db, async (txn) => {
  const productDoc = await txn.get(doc(db, 'inventory', 'laptop_x1'));
  if (productDoc.data().stock <= 0) {
    throw new Error('Item out of stock');
  }

  // Atomically decrement stock and record order
  txn.update(doc(db, 'inventory', 'laptop_x1'), {
    stock: increment(-1)
  });
  txn.set(doc(db, 'orders', 'order_5502'), {
    itemId: 'laptop_x1',
    status: 'paid'
  });
});

// 2. Atomic Batch Writes (Up to 500 operations in one roundtrip)
const batch = writeBatch(db);
batch.set(doc(db, 'logs', 'log_1'), { event: 'user_login' });
batch.update(doc(db, 'users', 'user_1'), { lastActive: new Date().toISOString() });
await batch.commit();

Cryptographic Audit Ledger

Syntrabase records all privileged administrative operations into an immutable, append-only HMAC-SHA256 ledger. Any attempt to modify audit rows invalidates the cryptographic hash chain:

Compliance Ready: Built-in tamper detection verifies ledger cryptographic validity for SOC 2, HIPAA, and ISO 27001 compliance standards. 
import { getAdminAudit } from '@syntrabase/admin-sdk';
